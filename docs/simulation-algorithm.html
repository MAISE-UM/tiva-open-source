TIVA — Simulation Algorithm

How client/model/ turns a dosing history and a PK model into plasma and effect-site concentration curves.

Research and educational software. The simulation reproduces published models for a typical patient. It is not validated for clinical decisions. See the clinical use disclaimer.

The model

For each drug TIVA simulates a three-compartment model plus an effect-site compartment. Succinylcholine adds an absorption compartment. State (Amounts, in mg):

VariableCompartment
A0Absorption (used only when k01 > 0)
A1Central (plasma)
A2, A3Peripheral compartments
A4Effect site

Parameters come from the database per patient (PKDrugModel): Vc in litres and the rate constants k01, k10, k12, k21, k13, k31, ke0 in 1/min. Inside the loop they are converted to 1/second.

One time step (PKSimIterate.tsx)

The step is 1 second, an explicit Euler update:

EFFECT_VOL_FACTOR = 10000          // effect site is 1/10,000 of the central volume
k   = k_per_min / 60               // 1/s
k14 = (ke0 / 60) / EFFECT_VOL_FACTOR
k41 =  ke0 / 60
k1  = k10 + k12 + k13 + k14

if (k01 > 0):                      // succinylcholine only
    A0 += -A0*k01 + mgInfused
    A1 += (A0*k01 + A2*k21 + A3*k31 + A4*k41) - A1*k1
else:
    A1 += ((A2*k21 + A3*k31 + A4*k41) - A1*k1) + mgInfused
A2 += A1*k12 - A2*k21
A3 += A1*k13 - A3*k31
A4 += A1*k14 - A4*k41

The updates are applied in order, so A2, A3 and A4 use the already-updated A1 (and A1 the updated A0). The effect site is tiny, so it receives drug from the central compartment through k14 but returns it at k41 = ke0, which makes its concentration relax toward plasma with rate ke0 without disturbing mass balance appreciably.

Concentrations after each step:

Cp = A1 / (Vc * 1000)                         // mg/mL
Ce = A4 / ((Vc / EFFECT_VOL_FACTOR) * 1000)   // mg/mL
Cp, Ce -> cnvtTCIUnits(.., tci_unit)           // x1000 for mcg/mL, x1e6 for ng/mL

The method follows Shafer and Gregg, J Pharmacokinet Biopharm 1992;20(2) and an Octave reference implementation (see the root README).

Driving the model (processTCI.tsx)

processTCI(doseTable, demographics, maxTime, minMissing, refTime) returns the filled TCI object.

  1. Demographic units. Weight in lb is divided by 2.20462; height in inches is multiplied by 2.54; age in months is divided by 12.
  2. Time to peak. getTPeak(model) is computed and stored in pkModel.tpeak (see below).
  3. Lead-in. If the first dose is after the reference time, a Start Infusion row at rate 0 is inserted at the reference time so the curve starts there.
  4. First pass. For every non-bolus row, timeToRun is the gap in minutes (timeSinceFirstEvent) to the next dose-table event; the last row gets 0.
  5. Second pass. Rows are expanded so the loop only has to handle “run this rate for this long”:
    • A Bolus always runs for 10 seconds (10/60 minutes) and its dose is spread evenly over those seconds. If an infusion is running, its rate is added to the bolus input for those 10 seconds, and a new Start Infusion row at the same rate continues from the bolus to the next event (shortened by the 10 seconds).
    • If no infusion is running, a zero-rate infusion row is inserted to cover the time until the next event.
    • After the last row, the simulation continues for maxTime + minMissing minutes at the infusion rate in force (0 if none). This is the dotted “projection” part of the graph.
  6. Main loop. For each expanded row the loop advances msec in 1,000 ms steps up to timeToRun:
    • Every 10,000 ms (and at the start) the drug input rate for the row is recomputed: for infusion events convertInfUnits() gives mcg/kg/min and the input is rate * weight / (60*1000) mg per second; for a bolus cnvBolusRate() gives total mg and the input is that amount divided by 10 seconds (plus the running infusion rate, if any).
    • Every second it adds getAmountInfused() mg, calls pkSimIterate(), and appends t (minutes), Cp and Ce to the output arrays.
  7. Cut-off. If the reference time is later than the first row, samples before it are removed (t, Cp, Ce are sliced and tmin shifted).

The unit lists that the UI offers for each drug come from core.Medications.Units in the database. Weight-based conversions use the patient's weight in kg; the absolute units (mcg/min, mg/hr and so on) divide by the weight, so a weight of 0 is not meaningful.

Time to peak effect (getTPeak.tsx)

Starting from empty compartments, the model is given 1 mg per second for the first 10 seconds and then nothing, and the effect-site amount A4 is recorded each second until it starts to fall. The returned array is that unit-response curve; its length is the time to peak effect in seconds (for the whole run including the 10 s input). It is recomputed for each model on every processTCI call and is used only by the effect-site TCI helper below.

Target-controlled infusion helpers

tciPlasmaIterate and tciEfctIterate compute the mg-per-second input needed to reach a target plasma or effect-site concentration (the effect-site version follows the Shafer and Gregg approach of finding the infusion whose predicted peak effect equals the target; it falls back to the plasma calculation when the predicted effect-site amount is already within 5% of target and returns 0 when the target is 0 or would already be exceeded). processTCI calls them for rows with event PlasmaTCI or EffectTCI. The dashboard does not create such rows and the target variables in processTCI are fixed at −1, so this path is inactive in the current UI and has no tests.

What the database contributes

  • Per-patient parameters. core.GetMedicationModels runs each model.PK_* procedure with the patient's weight, age, height and sex. Covariate adjustments (Schnider age terms, adjusted body weight, James or Janmahasatian lean body mass, age bands) happen there, not in TypeScript. pk-models.html lists the models.
  • Drug list and display ranges. core.Medications supplies units, default graphs and the Lower/Upper target band.

Tests

Unit tests in client/unit_tests/ cover the step function, time to peak and the unit helpers (client.html § Tests). They do not exercise processTCI end to end. The root README describes an external comparison against an Octave reference implementation on 101 cases (max deviation 0.103%, median 0.009%). That shows the web app reproduces the reference calculation; it is not a clinical validation.
