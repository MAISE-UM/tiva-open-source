TIVA — PK Models

The drugs and published pharmacokinetic/pharmacodynamic models used in development, how they are stored in SQL Server, and how patient-specific parameters reach the simulation.

Model sources are research literature. The parameters live in the database, not in the source, so each installation chooses its models. Cite the original publication for any model you use. TIVA is not a medical device and has not been validated for clinical decisions (disclaimer).

How models are stored

TableHolds
core.MedicationsOne row per drug: name, search terms used to match EHR drug names, dose units offered, standard concentration, display range (Lower, Upper, Typical, MEAC, EndCe), Load_Graph_Default, Active.
core.Medication_ModelsOne row per model: Medication_ID, Model_Name, static parameters (k01, Vc, k10…ke0), tci_unit (mcg/mL or ng/mL), covariate switches (useABWCorrection, useLBMCorrection, useWeightAdjusted, and use-flags for age, weight, height and sex), Default, and Stored_Procedure, the model.PK_* procedure that computes the patient-specific values.

Search terms (Medication_Search_Terms) are comma separated; every term must be contained in the EHR drug name (case-insensitive) and a term starting with ! must not be. This is how EHR orders are matched to TIVA drugs (matchMedication).

How parameters reach the simulation

  1. The client calls POST /Api/Meds/GetDrugModels with age (years), height (cm), weight (kg) and sex (m/f).
  2. The endpoint runs core.GetMedicationModels. For each row of core.Medication_Models it looks up Stored_Procedure in the database and executes it with @Model_ID, @weight, @age, @height, @sex, adding @useWeightAdjusted, @useABWCorrection or @useLBMCorrection only for models whose flag is set. A missing procedure produces a row with error = 'Stored procedure … not found' and all parameters −1. The procedure name is resolved through OBJECT_ID and quoted, so the column value cannot inject SQL.
  3. Each model.PK_* procedure returns one row: Model_ID, Name, Vc, k01, k10, k12, k13, k21, k31, ke0, Errors. If age, weight, height or sex is missing it returns −1 for every parameter and Need Weight Height Age Sex (whichever are missing) in Errors.
  4. core.GetMedicationModels joins the results with the model and medication names, tci_unit and the default_model flag and returns them. The client keeps them as PKDrugModel objects and uses the default model per drug until the user picks another.

Covariate helper functions (schema model)

FunctionFormula (as scripted)
model.calcAdjustedBodyWeight(sex, height_cm, weight_kg)IBW = 45.4 + 0.89 × (height − 152.4), +4.5 for males; ABW = IBW + 0.4 × (weight − IBW).
model.pkLbmJames(weight, height, sex)Male: 1.1 × W − 128 × (W/H)². Female: 1.07 × W − 148 × (W/H)².
model.pkLbmJanmahasatian(weight, height, sex)BMI = W / (H/100)². Male: 9270 W / (6680 + 216 BMI). Female: 9270 W / (8780 + 244 BMI).

Example: model.PK_Propofol (Schnider) reads Vc and ke0 from the model row, uses adjusted body weight when @useABWCorrection = 1, computes lean body mass with James, and derives v2, cl1, cl2 from age, weight, lean body mass and height, then k10 = cl1/Vc, k12 = cl2/Vc, k13 = cl3/Vc, k21 = cl2/v2, k31 = cl3/v3. model.PK_Remifentanil (Minto) uses age and lean body mass (James or Janmahasatian when @useLBMCorrection = 1) for compartment volumes, clearances and ke0.

Adding or changing a model

  1. Add a row to core.Medications if the drug is new (name, search terms, units, display range).
  2. Add a row to core.Medication_Models with the static values, tci_unit, flags, and Stored_Procedure = 'model.PK_YourDrug'. Set Default = 1 on exactly one model per drug.
  3. Create model.PK_YourDrug with parameters @Model_ID INT, @age, @weight, @height DECIMAL(10,4), @sex CHAR(1) (plus any flag parameters you use) returning one row with the columns listed above in that order (the caller inserts the result set into a temporary table by position).
  4. Grant the API's database user EXECUTE on the schema. The drug appears in the dashboard's “Select medication” list automatically when its core.Medications row is active and not deleted (Meds/GetMedications); its dose units come from Medications.Units.
  5. Cite the source publication and compare your output with a reference implementation before relying on it.
