TIVA — Client Brief

One-page orientation for the Next.js client in client/. The full reference is client.html.

What it is

A Next.js 16 App Router application (React 19, TypeScript) that renders the TIVA dashboard: patient covariates, per-drug dose tables, and Plotly graphs of simulated plasma (Cp) and effect-site (Ce) concentration. The PK simulation itself runs in the browser (client/model/). Drug parameters, medications, lists, users and permissions come from the API.

Mental model

  • Browser components never call the API directly. They call server actions in client/api/*.tsx ('use server'). The Next.js server attaches the JWT from the X-Access-Token cookie and calls the API.
  • Every API response is an envelope { bSuccess, sErrorInfo, oReturnObject } whose oReturnObject is a JSON string. processResponse<T>() in lib/utils.ts parses it.
  • Authorization is route-driven by the database. proxy.ts loads the user's permissions, writes them to the user-permissions cookie, and 404s routes the user may not see. Header links, buttons and dropdown items are rendered from those permissions (Application_Functions).
  • Configuration is build-time. All settings are NEXT_PUBLIC_* variables baked in by npm run build. EHR display names and data labels are the exception: they are fetched at runtime from GET /REST/ehr/client-config.

Commands

cd client
cp .env.example .env     # fill in the NEXT_PUBLIC_* values
npm install
npm run dev              # next dev --turbopack, http://localhost:3000
npm test                 # jest (unit_tests/)
npm run build            # bake NEXT_PUBLIC_* into the build
npm run lint

Things to know

  • The client needs a running API and database to do anything beyond the login page.
  • app/utils/auth.ts throws at start-up if NEXT_PUBLIC_JKU_URL is not set: the Next.js server verifies TIVA tokens (RS384) against the API's /.well-known/jwks.json.
  • The simulation code and several components log heavily with console.log. Expect noisy browser and server consoles in development.
  • Production hosting is iisnode via server.js; web.config is not in the client folder and comes from api/deploy/web.config.example.
  • TIVA is not a medical device (see the clinical use disclaimer).
