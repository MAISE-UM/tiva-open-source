TIVA — Graph Architecture

How PK simulation output flows into the Plotly graph: data generation (model/, lib/med-helpers.tsx) to data visualization (Graph.tsx, MedPlotly.tsx).

End-to-end flow

The simulation runs entirely in the browser. The only server calls on this path are drug-model parameters (before) and the graph log (after).

Data generation

  1. Drug models. Dashboard.refreshDrugModels() posts age (years), height (cm), weight (kg) and sex (m/f) to Meds/GetDrugModels. The database returns one row per model with Vc (L), k01, k10, k12, k13, k21, k31, ke0 (1/min), tci_unit, default_model and an error text when a model's stored procedure is missing. See pk-models.html.
  2. Dose tables. A DoseTable per drug holds the chosen model and rows (Bolus, Start Infusion, Dose Change, Stop Infusion). Rows come from user input or from EHR/MPOG data (createDoseTableEntries, prepareMPOGData). Each table owns a TCI state created by initTCI(model).
  3. Refresh. refreshDataHandler() → refreshData(). It drops tables in a failed state, resets every table's TCI, then calls processTCI() per drug. In EHR or MPOG mode it passes extra minutes (minMissing) so a still-running infusion is simulated up to now or the anesthesia end.
  4. Simulation. processTCI() appends one sample per simulated second to tci.t (minutes), tci.Cp and tci.Ce (converted to the model's tci_unit: mcg/mL or ng/mL). Details: simulation-algorithm.html.
  5. Trimming. If the reference time is later than the first dose, samples before it are removed so the graph starts at the reference time. If the first dose is later than the reference time, a zero-rate infusion row is inserted to fill the gap.
  6. Logging. After computing, the dashboard posts the inputs and dose tables to API/Logs/SaveGraphLog (api.LogGraph → api.Graph_Logs).

Data visualization

  1. Down-sampling. condenseArray() keeps at most 1000 evenly spaced samples of t, Cp and Ce.
  2. Time axis. Each sample time in minutes becomes new Date(referenceTime + minutes * 60000).
  3. Solid vs dotted. The sample closest to (last time − maxTime minutes) splits the series. Earlier samples are drawn as solid splines; the last maxTime minutes (the projection after the last recorded dose, set by “Time (min) Into Future to Generate”) are drawn dotted.
  4. Traces. Cp is orange, Ce is blue, both named “Plasma Concentration (Cp)” and “Effect Concentration (Ce)”. Each can be hidden with the graph options (plasmaStyle, effectSiteStyle = Show/Hide).
  5. Target band. With concentrationTarget = Show a translucent rectangle spans the medication's Lower to Upper values (from core.Medications).
  6. Layout. Y axis titled Concentration (<tci_unit>), starting at zero; title is the drug name (with the model name in full-size view); modebar hidden; responsive.
  7. Rendering. MedPlotly loads plotly.js-dist-min with next/dynamic and ssr: false, calls newPlot whenever data, layout or config change and purge on cleanup, and shows a spinner while drawing.
  8. Interaction. “Preview Changes” opens MedicationGraphModal (full size, editable dose table, reference-time picker, PNG capture with html2canvas). Users with the ExportGraphToFileButton permission also get “Export to File”, which downloads the Plotly trace data as JSON.

Concentration units. The simulation works in mg and mL internally. cnvtTCIUnits multiplies mg/mL by 1,000 (mcg/mL) or 1,000,000 (ng/mL) depending on the model's tci_unit. The axis label shows the same unit.
