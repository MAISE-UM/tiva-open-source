Overview

24 tables, 3 functions and 49 stored procedures in four schemas. Requires SQL Server 2017 or later (STRING_AGG, STRING_SPLIT) and database compatibility level 130 or higher.

SchemaHoldsTables
adminUsers, roles, clients, UI functions and routes, configuration, lists, external-use logs13
apiDynamic endpoint definitions, parameters, endpoint security, and logs (errors, graph inputs, user activity, logins)7
coreMedications, PK models, dashboard lists4
modelPer-drug PK parameter procedures and body-weight helper functions0

api.UserLogin_Log stores the patient ID, MRN and name sent by the EHR at launch (api.Log_Login), and api.Graph_Logs stores case identifiers. Treat the database as holding protected health information, or change those procedures to not store the values.

Setting up

CREATE DATABASE TIVA;
sqlcmd -S <server> -d TIVA -E -i CreateDB.sql      -- schema, functions, procedures (no data)
sqlcmd -S <server> -d TIVA -E -i SeedData.sql -f 65001   -- roles, endpoints, medications, models, lists
-- then create the first administrator with admin.AddUser (see the end of ExportSeedData.sql output)
-- and grant the API's database user EXECUTE on schemas admin, api, core and model

Messages that a module “depends on the missing object api.SaveUserLog” are expected while CreateDB.sql runs. Config values with secrets in admin.Application_Configurations are exported as NULL and must be set per installation.
