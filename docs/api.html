TIVA — API Reference

Developer reference for the ASP.NET Core API in api/TIVA_API: controllers, the database-driven endpoint engine, configuration, hosting, and the seeded endpoint catalog.

Overview

Project TIVA_API targets net10.0 (C# 14), uses the ASP.NET Core MVC controller model, and talks to SQL Server through a small ADO.NET wrapper (Helpers/DAL.cs). Almost all application data access is not hard-coded controllers: endpoints, parameters and role access are rows in the database (api.Endpoints, api.EndpointParameters, api.EndpointSecurity) and one generic controller executes them. Authentication, EHR login, logging, reCAPTCHA and a few admin utilities are normal controllers.

Every response uses the envelope ReturnInfo (Models/ReturnInfo.cs):

{ "bSuccess": true, "sErrorInfo": null, "oReturnObject": "<JSON string>" }

For stored-procedure endpoints oReturnObject is a JSON string: Newtonsoft serialization of a DataTable (result type data) or DataSet (result type dataset, tables optionally named by DataSet_Table_Names, separated by ;). Clients parse it a second time (the TIVA client does this in processResponse). JSON is serialized with ReferenceHandler.Preserve.

Request pipeline (Startup.cs)

  1. HTTP logging, forwarded headers (X-Forwarded-For, X-Forwarded-Proto).
  2. Development only (ASPNETCORE_ENVIRONMENT=Development): developer exception page, Swagger UI at /swagger.
  3. Session (idle timeout 60 minutes, HttpOnly, in-memory), CORS and Access-Control-Allow-* headers for AppSettings:SITE_URL (comma-separated origins allowed, credentials allowed), HTTPS redirection.
  4. Routing, authentication (JWT bearer + cookie scheme, token read from the X-Access-Token cookie, RS384, RequireHttpsMetadata=false, ValidateLifetime=false), authorization. A global filter requires an authenticated user on every action that is not marked [AllowAnonymous].
  5. Endpoints: MapControllers() plus the EHR routes mapped from Ehr:Routes (only if Ehr:Enabled).
  6. After start-up, EndpointCache.WarmCache() loads the endpoint definitions from the database. A failure is logged to the console but does not stop the app.

Singletons: EndpointCache, AccessCheckerService. Scoped: SessionCache (over AddDistributedMemoryCache), SmartOnFhirService. Transient: IRepository, ITokenService. Everything is held in process memory, so the API must run as a single instance (one server, one IIS worker process). Restarting it signs users out.

Endpoint engine

The generic controller turns a request such as POST /Api/Meds/GetDrugModels into a database call.

  1. Authenticate. The action is anonymous at the framework level so that anonymous endpoints can exist. The user name comes from the token's name claim, or anonymous. If the token has an exp claim in the past the call returns 401.
  2. Find the endpoint. EndpointCache maps the name {schema}/{endpoint} to an Endpoint object. Unknown names return bSuccess=false.
  3. Authorize. Allow_Anonymous endpoints pass. Otherwise one of the token's role claims must be in the endpoint's RolesWithAccess (403 if not).
  4. Execute by Call_Type:
    • StoredProcedure: builds EXEC <proc> [@User] [, @Slug] , @Param… with typed SQL parameters from api.EndpointParameters (types int, double, string, date, datetime, bool). UseParam0UserPass passes the caller's user name as @User. A required parameter that is missing aborts the call with “missing required parameter”; optional ones become NULL. A parameter value equal to its Null_Value is sent as NULL. Results are serialized as described in the overview. The connection comes from Connection_Name (DatabaseSettings:DEFAULT).
    • REST: calls an external HTTP API with RestSharp. The URL is {URL base}{URL}, where the base is looked up by URL_Base in admin.Application_Lists (category APIEditor, section URLBases) and cached. Parameters go to the query string, JSON body or URL path by Parameter_Destination (Parameter, Body, URL); one URL parameter is appended as /{value}. System-provided parameters take a fixed Template (with {var} replaced by the caller's name for Is_User_Pass) and can be objects or lists of objects, for APIs with structured request bodies.
  5. Credentials for REST calls (Credential_Source): None; AdminConfigTable (an encrypted value in admin.Application_Configurations); UserSession (a property of the caller's cached Session, for example FhirAccessToken, refreshed first if older than Ehr:TokenRefreshMinutes); CacheToken (a cached value). The token is sent as a bearer header.
  6. Respond with the ReturnInfo envelope.

Adding or changing an endpoint

  1. Add the rows (in the /admin/api-edit UI, with api.AddEndpoint, api.AddParameter and api.AddSecurityRole, or by SQL): endpoint, parameters, and the roles that may call it.
  2. Call POST /Admin/ReloadEndpoints (or recycle the app pool). The cache is otherwise only filled at start-up.
  3. Call /Api/{schema}/{endpoint}. Check GET /Admin/GetCurrentEndpoints to see what the API has loaded.

The client's /admin/api-edit screen does the same with a review step that shows the diff before saving.

Generated from api/TIVA_API/examples/SeedData.sql. A real installation may differ: endpoints are data.

Configuration

Settings come from appsettings.json (local runs; template api/deploy/appsettings.example.json) and from environment variables with the MA_ prefix, where Section:Key becomes MA_Section__Key and list items get an index (MA_Ehr__User__StripPrefixes__0). Environment variables win. On a server use the IIS web.config only (api/deploy/web.config.example) and do not deploy an appsettings.json.

Hosting and deployment

  1. Install IIS with URL Rewrite and iisnode, the ASP.NET Core Hosting Bundle (for the .NET version in api/global.json) and Node.js.
  2. dotnet publish TIVA_API -c Release -o publish; delete any appsettings.json from publish; copy to the API folder so TIVA_API.dll sits directly in it.
  3. Two app pools, both No Managed Code: client, and API (Integrated pipeline, Maximum Worker Processes = 1, identity with database access if you use integrated security).
  4. Site root = the Next.js build with HTTPS binding; add the API as an application with alias REST. Put web.config (from web.config.example) in the client folder. It routes /REST to the API and everything else to server.js, and holds the MA_* settings.
  5. Recycle both pools and open https://<host>/REST/Admin/Health: it should return Healthy.

Single instance only: sessions (including EHR tokens), OAuth state and the endpoint cache are in memory. Do not use a web farm or web garden. After editing api.Endpoints*, call POST /Admin/ReloadEndpoints or recycle the pool.
